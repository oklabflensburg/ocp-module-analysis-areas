Analysis Areas 1.5.3 fixes the Statistics SDK UUID/string boundary.

Statistics 0.2.0 returns `StatisticsArea.id` values as UUID objects in both the
summary and time-series result types. Analysis Areas previously passed those SDK
dataclasses directly into module-owned Pydantic response models whose public HTTP
contract uses strings, causing `/statistics` requests to fail validation with HTTP
500. A small module-owned adapter now converts exactly the two nested area IDs to
strings while preserving dates, decimals, optional source metadata, and metric data.

Regression coverage exercises both Statistics result types with real UUID objects.
The pinned, built-in-free Host contract additionally installs Statistics 0.2.0 and
Analysis Areas externally, queries real PostgreSQL statistics through the public SDK
service, and verifies the summary and time-series HTTP endpoints return 200 with
string UUID fields. The existing PostGIS `Box3D` Analytics regression remains part
of the same release gate.

This patch contains no migration and requires no data reset. It is compatible with
the existing database state from v1.5.2 and is required for the final external-module
Host cutover tracked in `oklabflensburg/open-city-planner#197`.
